# 제조자 콘솔 UX 보강 — 결정 2026-09-17

*(09-14 컨설팅 "제조자 쪽이 너무 약하다 — 확인하고 버튼 누른다밖에 없다"에 대한 답.
호진의 현장 경험(09-17 문답)을 근거로 확정. 아이패드 미니 가로 1133×744 기준.)*

## 0. 진단

컨설턴트 지적은 맞다. 콘솔의 정상 경로가 "자동값 보고 → 단계 완료"뿐이고, 예외는 편차 하나다.
그런데 **현장에서 실제로 일어나는 일**은 이보다 훨씬 많다 — 기기 0점, SOP 확인, 시약 로트 대조, 재측량,
의뢰자에게 물어보기. 지금까지 이걸 화면에 안 올린 것이지 없는 게 아니다.

이 문서는 그중 **결정·예외·의뢰자 순환**이 있는 셋을 골라 화면으로 만든다. 나머지는 하지 않는다.

| | 무엇 | 왜 UX인가 |
|---|---|---|
| A | **제조 준비 체크** | 시작 전 4단계 확인. 만료 로트를 시스템이 막고, 재고 부족은 의뢰자에게 묻는 예외로 빠진다 |
| B | **재측량 루프** | 이탈값 앞에서 세 갈래 결정. 10회 넘으면 "값이 아니라 기기를 의심하라"고 방향을 튼다 |
| C | **공정 중 의뢰자 확인 요청** | 끝에 가서 발견하면 재제조뿐이다. 공정 중에 묻고 답을 받아야 한다 |

## 1. 현장 문답에서 확정된 사실

| 질문 | 답 (호진, 09-17) | 설계 반영 |
|---|---|---|
| 준비 순서 | **0점(저울·pH) → SOP 확인 → 시약 준비 → 제조 LOT 확인** | A의 4단계 순서 그대로 |
| LOT 번호 | 두 종류. 시약 로트(공급사, 유효기간용) / **제조 LOT(우리가 부여, 의뢰자 실험 서류에 동기화되는 추적 번호)** | A④는 후자를 "이 번호가 실험 서류로 갑니다"로 보여준다 |
| 교정 주기 | 하루 1회 기준. 저울은 대체로 안정, **pH미터는 민감해 재교정이 필요할 때가 있다.** 교정 이력(누가·몇시)이 태블릿에 남아 자료가 되면 좋겠다 — 실험실의 기구 사용기록서 | `instrument_calibrations` 테이블 신설. 모든 측정값이 어느 교정 아래에서 찍혔는지 링크 |
| 재측량 한도 | **한 단계 안에서 10회.** 넘으면 0점 체크로 유도 | 단계별 카운터. 10회 도달 시 버튼이 `[0점 체크로]`로 바뀜 |
| 보완 요청 | **사실상 재제조다.** 공정 중 소통으로 잡지 않으면 마지막에 발견된다 | 리뷰 시점 "보완 요청" **제거**. 대신 C를 만든다 |
| 확인 요청 중 공정 | **의뢰자 답을 기다린다.** 이때 알람이 가야 한다 | 배치 상태 `waiting_client` 신설. 1차 알람은 인앱 Realtime(CLAUDE.md) |

## 2. 화면

### A. 준비 탭 — 배치 상세의 첫 탭

탭이 `준비 · 공정 · 편차 · 요약 · 결과` **5개**가 된다. 잠금 사슬이 한 칸 앞으로 — **준비 완료 전엔 공정이 잠긴다.**
744pt 안에 4단계가 들어가야 하므로 **현재 단계만 펼치고** 나머지는 한 줄로 접는다(공정 탭의 "현재 단계에만 입력 박스" 패턴과 같다).

```
LOT-2607-04  준비중                    TAE 50X · pH 8.30 · 1000 mL
[준비 1/4] 공정🔒 편차 요약🔒 결과🔒
────────────────────────────────────────────────────────────
● 1. 계측기 0점 · 교정                                    진행중
  ┌────────────────────────────────────────────────────────┐
  │ BAL-204  전자저울     마지막 0점  2시간 전 · 최제조   [0점 확인] │
  │ pH-2000-A pH미터      마지막 교정  어제 09:12 · 최제조         │
  │                       24시간 경과 — 재교정 필요       [교정 기록] │
  └────────────────────────────────────────────────────────┘
○ 2. SOP 확인                          레시피 6단계 · 주의사항 2
○ 3. 시약 준비                          칭량 시약 3 · 로트 미선택
○ 4. 제조 LOT 확인                      LOT-2607-04
```

- **①** 기기별 마지막 기록을 보여주고, pH미터가 24h 넘었으면 재교정을 요구한다. 확인/기록 = `instrument_calibrations`에 행 추가(누가·몇시).
- **②** 레시피 단계 + 주의사항(EDTA는 Tris 녹인 뒤 · Tris는 온도 평형 후 pH)을 태블릿에서 읽고 `[확인]`. 시각·사람이 남는다.
- **③** 칭량 시약마다 로트를 고른다. 시스템이 `expires_on`을 판정 —
  - 유효 → ✓
  - **만료 → 차단.** `[대체 로트]` 또는 `[편차 등록]`(DEV-03 시나리오가 여기서 태어난다)
  - **재고 없음 → `[의뢰자 확인 요청]`**(C로 이동. "R&D팀 로트 차용해도 될까요?")
- **④** `LOT-2607-04`를 크게 띄우고 "이 번호가 의뢰자 실험 서류에 동기화됩니다" — 제조자가 한 번 더 본다.
- 4/4 완료 → `[공정 시작]` → 배치 `preparing → running`, 공정 탭 열림.

### B. 공정 탭 — 이탈값 처리

```
● 4. pH 조정                                              편차
  ┌────────────────────────────────────────────────────────┐
  │ pH · 계측기 연동 · 범위 이탈           재측량 3/10        │
  │  8.12                                  허용 7.95–8.05    │
  │  ⚡ pH-2000-A 자동 기록 15:10 · 교정 09:12 기준           │
  │                                                          │
  │  이전 시도  8.14 (15:06)  8.13 (15:08)   ← 덮어쓰지 않는다 │
  │                                                          │
  │ [재측량]  [수동 입력 — 사유 필수]  [편차 등록]              │
  └────────────────────────────────────────────────────────┘
```

- **[재측량]** 새 측정 행이 추가된다. 이전 값은 그대로 남는다 — 스티커를 떼지 않는 원칙.
- **10회 도달** → `[재측량]`이 **`[0점 체크로 돌아가기]`**로 바뀌고 준비 탭 ①로 보낸다. 재교정 후 카운터가 0이 된다(새 `calibration_id`).
- **[수동 입력]** 사유 필수. `source='manual'`, `instrument_id` 유지 → DB의 `override_needs_reason` 제약이 건다.
- **[편차 등록]** 기존 경로.
- 계측기 연동은 스코프 밖이므로 데모에선 재측량 시 시드값을 ±0.02 흔들어 보여준다.

### C. 의뢰자 확인 요청 — 공정 중 어느 단계에서든

현재 단계 박스 하단에 항상 있다: `[의뢰자에게 확인 요청]`

```
제조자                                의뢰자 (대시보드 "조치 필요")
┌──────────────────────┐              ┌──────────────────────────────┐
│ 확인 요청             │   Realtime   │ 🔔 제조자 확인 요청 · LOT-2607-04 │
│ NaCl 재고 부족.       │ ──────────▶ │ 3. 시약 준비 · 최제조 · 4분 전     │
│ R&D팀 로트 NACL-2609 │              │ "NaCl 재고 부족. R&D팀 로트      │
│ 차용해도 될까요?      │              │  NACL-2609 차용해도 될까요?"     │
│                      │              │ [진행하세요]  [멈춰주세요 + 사유]  │
│ ⏸ 의뢰자 답변 대기 중 │ ◀────────── │                                  │
└──────────────────────┘              └──────────────────────────────┘
```

- 보내는 순간 배치가 **`waiting_client`**로 바뀌고 공정이 멈춘다. 단계 완료 버튼 잠금.
- 의뢰자 쪽엔 새 화면이 없다 — 조치 필요 카드 한 종류가 늘고, 의뢰 상세 타임라인의 해당 단계에 **인라인**으로 붙는다(편차와 같은 자리).
- `진행하세요` → 배치 `running` 복귀, 답변이 제조자 박스에 표시.
- `멈춰주세요` → 배치는 계속 `waiting_client`. 제조자가 편차로 전환하거나 의뢰자가 재제조를 낸다. 사유 필수.
- 알람은 1차 인앱 Realtime. 이메일은 Phase 2(CLAUDE.md 그대로).

### 손대지 않는 것
- 교반 타이머 — 유틸리티. 서사가 아니다.
- 의뢰자 포털 구조 — 카드 종류 하나, 타임라인 항목 하나 추가뿐.

## 3. 데이터 모델 변경 (마이그레이션 0007)

| 변경 | 내용 |
|---|---|
| `recipe_reagents` 신설 | 레시피의 시약을 **행으로** 푼다 — `name, amount, unit, kind, seq`. 지금은 `recipe_steps.reagent`에 "NaCl 4.00 / KCl 0.10 / …" 문자열로 뭉쳐 있어 로트를 시약별로 고를 수 없다 |
| `batch_reagents` 신설 | 이 배치에서 각 시약에 고른 로트 — `batch_id, recipe_reagent_id, reagent_lot_id, confirmed_by, confirmed_at` |
| `instrument_calibrations` 신설 | `instrument_id, kind('zero'\|'calibration'), performed_by, performed_at, note`. 기구 사용기록서의 디지털판 |
| `measurements.calibration_id` | 어느 교정 아래에서 찍힌 값인지. 재측량 카운터 리셋의 기준이기도 하다 |
| `measurements.attempt` | 단계 안 재측량 회차 |
| `batches` 컬럼 3개 | `sop_confirmed_at/by`, `lot_confirmed_at/by`, `prep_completed_at` |
| `batch_status` enum | `waiting_client` 추가 |
| `inquiries` 신설 | `batch_id, process_step_id, question, asked_by, asked_at, decision('proceed'\|'hold'), answer, answered_by, answered_at` |
| `client_review_status` | `revision_requested` 값은 남기되 UI에서 쓰지 않는다. 데이터 호환용 |
| 함수 | `record_calibration`, `confirm_prep_step`, `select_batch_reagent`, `start_process`, `remeasure`(시드 흔들기), `ask_client`, `answer_inquiry` |

## 4. 스펙 변경 — CLAUDE.md 반영

1. 배치 상세 탭 **4 → 5** (`준비` 추가). 잠금 사슬: 준비 → 공정 → 요약 → 결과.
2. 의뢰자 액션 **3 → 2**. `리뷰 완료·서명` / `재제조 요청`. "보완 요청은 사실상 재제조"(호진).
3. 배치 상태에 `waiting_client` 추가.
4. 측정값 원칙에 한 줄: **"측정값은 덮어쓰지 않는다. 재측량은 행을 추가한다. 모든 측정값은 교정 이력에 링크된다."**

## 5. 데모 서사 (마일스톤 ⑥ E2E)

```
REQ-046 재제조 수락 → LOT-2607-06 생성
 → 준비 ① pH미터 24h 경과 → 교정 기록
 → 준비 ③ NaCl 로트 NACL-2506 선택 → 만료 차단 → 대체 로트 → ✓
 → 준비 ④ LOT 확인 → 공정 시작
 → 공정 4 pH 8.12 이탈 → 재측량 ×2 → 8.03 ✓ → 단계 완료
 → 공정 5 앞에서 [의뢰자 확인 요청] "전도도 기준 하한 근접, 그대로 진행할까요?"
    → 의뢰자 대시보드에 카드 → [진행하세요]
 → 완료 → 요약 확정 → 결과 입력 → 1차 검토(서명)
 → 의뢰자 리뷰(서명) → 완료
```

한 배치 안에 **결정 3번, 예외 2번, 의뢰자 순환 1번**이 들어간다. 이게 컨설턴트가 말한 "UX가 드러나는 화면"이다.

## 6. 구현 순서

1. 0007 마이그레이션 + 시드 보강(레시피 시약 행, 교정 이력 2건) + 목업 반영
2. 준비 탭 (A)
3. 공정 탭 재측량 분기 (B)
4. 확인 요청 — 콘솔 송신 + 의뢰자 수신·답변 (C)
5. ReviewDialog에서 보완 요청 제거
6. 목업 모드로 캡처 → 컨설턴트 전달

의뢰자 포털 신규 화면(새 의뢰·캘린더·준비 가이드)과 Realtime은 이 뒤다.
