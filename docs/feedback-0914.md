## 1. 의뢰자 대시보드 — 상태 분류를 깨지 않는다

### 지적
B안은 "조치 필요"(검토 대기·일시 중지)를 위로 빼고 진행 중·완료를 아래로 접었다. 그러면 **진행 중인데 조치가 필요한 건이 진행 중 목록에서 사라진다.** 4개 상태(요청됨/진행 중/검토 대기/완료)의 기준이 깨지고, 조치 후엔 다시 아래로 내려가면서 데이터가 위아래로 오르내린다.

### 결정
- 상태는 **상호 배타적 4개**로 고정한다. 한 의뢰는 정확히 한 상태에만 속한다.

  | 상태 | 판정 |
  |---|---|
  | 수락 대기 | `request.status = pending` |
  | 진행 중 | `accepted` 이고 제조자 1차 검토 서명 전 |
  | 리뷰 필요 | 1차 검토 서명 완료, 의뢰자 리뷰 전 |
  | 완료 | `client_review_status = reviewed` |

  반려(`rejected`)와 보완 요청(`revision_requested`)은 각각 수락 대기·진행 중의 **부속 표시**다. 별도 상태를 만들지 않는다.

- **대시보드의 "조치 필요"는 상태가 아니라 뷰다.** 리뷰 필요 + 반려를 모아 보여줄 뿐, 그 건은 여전히 자기 상태 목록에도 있다. 그래서 어디서도 사라지거나 튀어오르지 않는다.

- 대시보드(홈) 구성
  1. 상단 — **상태별 현황 요약** (4개 카운트). 확인용.
  2. 하단 — **내 조치가 필요한 의뢰**. 단순 목록이 아니라 **도식이 들어간 카드**로 최대 5개 + 페이지네이션. "바로 들어와서 알아야 할 것"이라 상세가 드러나야 한다.
  3. **완료 건은 대시보드에 쌓이지 않는다.** 완료 탭에서 본다.

- **탭 메뉴**로 나눈다(토글 아님). `대시보드 · 진행 중 · 완료`. 상태 탭을 누르면 그 상태 카드만 리스트로 깔린다.

- 포트폴리오 화면은 **두 벌만** — 대시보드 + 진행 중 목록. 나머지 상태 목록은 같은 컴포넌트다.

### 검색
통합 검색 하나를 탭 메뉴 옆에 둔다. 상태별 검색창을 두면 "완료만 검색" "진행 중만 검색"이 되어버린다. **MVP에서는 만들지 않는다.** 자리만 잡는다.

### 보드/테이블
보드 뷰는 만들지 않는다. 카드가 이미 카드이므로 리스트만.

## 2. 의뢰 상세 — 스티키 패널 + 모달

### 지적
- 1080p에서 잘린다. 검토 단계가 아닌 사용자에게는 검토 영역이 **텅 비어 미완성처럼 보인다.**
- 모바일에서 진행 상황을 다 내려서 본 뒤 검토하려면 다시 끝까지 올라와야 한다.
- 장비 경보(이슈)가 상단 큰 블록으로 박혀 있는데, 오류는 **어느 단계에서든 복수로** 날 수 있다.

### 사용자 3타입
| 타입 | 상태 | 검토 버튼 |
|---|---|---|
| a | 검토 단계 전 | **비활성** — "아직 검토 단계가 아닙니다" |
| b | 검토 필요 | 활성 + 안내 "제조가 완료되었습니다. 결과를 확인하고 서명해 주세요" |
| c | 검토 완료 | 활성 — 읽기 전용으로 결과 열람 |

### 결정 — 데스크톱
```
┌─────────────────────────────┬──────────────────┐
│  진행 상황 (타임라인)          │  [스티키]         │
│   · 의뢰 접수                 │  요청 정보 요약    │
│   · 수락 · 배치 생성           │  (작게 — 본인이   │
│   · 공정 3/5 ─ [오류 ▾]       │   낸 요청이니)    │
│       └ 편차 원인·조치 펼침    │  진행률 바        │
│   · …                        │                  │
│                              │  [검토 내용 확인]  │
│  코멘트                       │  ← 3타입 분기     │
└─────────────────────────────┴──────────────────┘
```
- 좌측이 스크롤 축. 우측은 `position: sticky`.
- **제조 결과 + 리뷰 액션(리뷰 완료·서명 / 보완 요청)은 모달**로 연다. 인라인 패널이 아니다.
  검토 단계가 아닌 사람에게 빈 영역을 보여주지 않기 위해서다.
- **재제조 요청**은 모달 안 구분선 아래. 완료 건에서도 열린다(CLAUDE.md).
- **편차는 타임라인의 해당 단계에 인라인**으로 붙는다. 단계 행에 `[오류]` 버튼 → 펼치면 원인·조치. 별도 이슈 섹션은 만들지 않는다.
- "제조 기록 요약" 블록은 타임라인과 중복이라 뺀다.

### 결정 — 모바일
- 스티키 패널이 **하단 고정 CTA 바**가 된다(쿠팡·무신사 구매하기 패턴). 요약 한 줄 + 버튼.
- 버튼을 누르면 결과 화면이 **다음 스텝(전체 화면)**으로 열린다. 모달이 아니다.
- 타임라인은 위로 쭉 스크롤.
