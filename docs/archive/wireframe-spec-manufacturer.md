# 와이어프레임 확정 스펙 — 제조자 콘솔
*(기획서 12번 "와이어프레임 미작성" 항목 해소분 — 시각 자료: manufacturer-console-wireframe.html)*

## 전제
- 아이패드 미니 **가로 모드 전용** (1133×744pt), 실습실 거치대 사용 가정
- 웹 기반이므로 기기 회전은 막을 수 없음 → 세로 감지 시 "가로 모드로 돌려주세요" 안내 오버레이 표시
- 로우파이 단계: 레이아웃 구조만 확정. 컬러/타이포는 디자인 토큰 단계에서 별도 결정

## 글로벌 프레임: 아이콘 레일 + 스플릿뷰
- **좌측 아이콘 레일 (~88pt)**: 홈 / 의뢰함 / 배치 / 편차 / 장비(P2) — 5개 고정
  - 의뢰함에 미처리 건수 배지 표시
  - 풀 사이드바 대신 아이콘 레일 채택 사유: 콘텐츠 폭 확보 + 장갑 착용 시 큰 아이콘 타겟 유리
- **중앙 리스트 (~320pt)**: 상태 필터 칩 + 카드 목록
- **우측 상세 패널 (~730pt)**: 선택 항목의 작업 공간
- 모든 터치 타겟 44pt 이상

## 화면 1: 대시보드 (홈)
- 상단 KPI 3개 고정: 신규 의뢰 대기 / 진행중 배치 / 미해결 편차(경고색)
- 하단 "처리 필요" 리스트: 의뢰·편차·공정 유형 혼합, 긴급도 순 정렬
- 각 행에 액션 버튼(검토/조치/계속) → 해당 작업 공간으로 직행
- 원칙: 대시보드는 조회용이 아니라 **작업 진입점**

## 화면 2: 신규·재의뢰함
- 리스트 필터: 신규 / 재의뢰 / 처리됨
- 재의뢰 건은 경고색 배지 + 이전 반려 사유·의뢰자 코멘트를 상세에 함께 노출
- 상세: 레시피/요청사항 카드 + 하단 액션 2개
  - **수락 → 배치 생성**: 수락 즉시 LOT 번호 발급, 별도 "배치 만들기" 단계 없음
  - **반려**: 사유 입력 모달 필수 → 의뢰자 포털 코멘트 스레드로 전달

## 화면 3: 배치 상세 (핵심 작업 공간)
- 기획서의 화면 5~8(공정/편차/요약/결과)을 **배치 상세 안의 탭 4개로 통합**
- 헤더: LOT 번호(모노스페이스) + 상태 배지 + 타겟 파라미터(모노스페이스)
- **탭 잠금 규칙**: 워크플로우 순서 강제
  - 공정 완료 전 → 요약·결과 탭 비활성(🔒)
  - 요약 확정 전 → 결과 탭 비활성
- 공정 탭: 세로 스텝 리스트, 완료 단계는 타임스탬프와 함께 취소선 처리
  - **현재 진행 단계에만** 입력 필드 + 액션 버튼 인라인 노출 (점선 박스)
  - 액션: [단계 완료] [편차 등록] — 편차 등록이 공정 흐름 안에 있어 화면 이탈 없음
- 편차 탭: 편차 기록 리스트, 원인·조치 입력, open/resolved 상태 추적
- 결과 탭: 결과 입력 + 1차 검토 서명 → 의뢰자 최종승인 요청 발송

## 데이터 표기 규칙
- LOT 번호, 수치(pH, 부피 등)는 모노스페이스 폰트 (기획서 4번 디자인 방향 반영)
